# RPH Pipeline — Design Spec

_2026-10-03 · Sub-project 1 of 3 (RPH pipeline → Progress → PWA app). Decisions and reasons: [discussion.md](../../discussion.md) ("Design spec: split, RPH pipeline first", "Grilling round", "Pacing round"). Where each part lives: [architecture.md](../../architecture.md) §4.4–4.6._

## 1. Goal

One command generates the coming week's RPHs for every class the teacher teaches, keeps a per-class lesson log (rekod) that the teacher edits after teaching, and prints how far each class is ahead of or behind the frozen RPT. It replaces the Apps Script stopgap.

**In scope:** Jadual parser, timetable resolver, class / event / activity / rekod files, lesson scheduler, RPH pacing planner, rekod sync, ahead/behind summary, RPH HTML renderer, `src/cli/rph.js`, the RPT "Peruntukan SP" appendix.

**Out of scope:** dashboard, history import from Sheets, PWA, IndexedDB, Drive sync, RPT freeze workflow, AI-written activity text, PJPK DSKP (not available yet).

## 2. Rules (summary)

| # | Rule |
|---|---|
| R1 | The RPT is fixed. It is read from the generated `rpt-<subjek>-<tahun>.md`, never regenerated by the RPH pipeline. |
| R2 | RPHs follow each class's **actual** progress, in DSKP order. The RPT only sets how much time each SP gets. |
| R3 | SP time for a class = the class's **real minutes in the RPT weeks where the SP sits**: SPs are laid in DSKP order over the RPT's capacity weeks using the **Peruntukan SP** weeks; each week contributes its overlap × the class's scheduled PdP minutes that week (holidays, exams and Batal removed). Partial weeks give less time, so an undisturbed class tracks the RPT week by week. Light SPs share a lesson; heavy SPs span lessons. |
| R4 | No continuation shorter than 15 min (finish the SP in this lesson); no new SP started with < 15 min left in the lesson. |
| R5 | A split SP is written plainly on every lesson it spans. **No "bersambung" / "samb." on lessons** (RPH or rekod). |
| R6 | A **ditunda** or **batal** lesson uses no time: the next lesson starts where the skipped one would have. An interrupted lesson is ditunda. |
| R7 | **Tutorial** repeats all SPs of the latest **diajar** pdp lesson before it; it never advances. |
| R8 | **Peperiksaan** lessons (exam day for the class's form) get no SP and never advance. |
| R9 | DSKP finished → each further pdp lesson revises one topic, cycling in order (`1.0`, `2.0`, …). |
| R10 | No RPT → one SP per lesson. No DSKP → rows with no SP. Both warn. |
| R11 | New rows are **diajar**, Kehadiran = class size. The teacher edits only exceptions. |
| R12 | Rows dated ≤ today are never changed. Rows dated after today are rebuilt on every run unless the teacher edited them (§5.4). |
| R13 | Ahead/behind is printed by the CLI only, never on the RPH. It is measured in minutes (content taught − PdP minutes scheduled so far) and shown in weeks of the class's normal timetable. |
| R14 | Only classes listed in the class file are planned; other timetable slots are skipped with one note. |

## 3. File formats

All files are UTF-8 markdown; parsers accept LF and CRLF. Table rows are `| a | b | … |`. Paths inside the class file are relative to the class file's folder (absolute paths also work).

### 3.1 Jadual — `jwg-<yyyymmdd>.md` (frozen: `sample/jwg-20261002.md`)
- Line `- Berkuat kuasa: yyyy-mm-dd …` = effective-from date.
- Only the table under `## Kelas` is read: `| Hari | Waktu | Masa | Subjek | Kelas | Bilik |`. One row = one lesson.
- `Waktu` is `a–b` (en dash or hyphen) or a single period `a`. Period p starts at 6:30 + 30p min; `Masa` must equal the computed 12-hour range (`7:30–8:30`, `12:30–2:00`) or parsing fails.
- `## Bukan kelas` and every other section is ignored.

### 3.2 Class file — `kelas-<tahun>.md` (new: `sample/kelas-2026.md`)
```
- Tahun: 2026
- Guru: FALHAIND RUBIN
- Takwim: takwim-smly-2026.md
- Jadual: jwg-20261002.md            (several versions: comma-separated)
- Acara: acara-2026.md
- Rekod: ../rekod/2026                (folder for rekod files)
- Output: ../output/rph               (folder for RPH HTML)

| Kelas | Nama penuh | Tingkatan | Subjek | Nama subjek | DSKP | Aktiviti | RPT | Tutorial | Bil. murid | Mula |
|---|---|---|---|---|---|---|---|---|---|---|
| 4S | 4 STANFORD | 4 | M3 | MATEMATIK | dskp-mat-t4.md | aktiviti-umum.md | ../output/rpt-mat-t4-2026.md | | 35 | 6.2.1 |
| 4H | 4 HARVARD | 4 | SK | SAINS KOMPUTER | | aktiviti-umum.md | | TUTORIAL | 30 | |
```
- One row per class × subject. `Subjek` = the jadual code. `Tutorial` = the jadual code whose slots are tutorials of this class × subject. Timetable slots of classes not listed here are not planned.
- **2026 file (as delivered):** only **4S Matematik** (Bil. murid 32, Mula 1.1.1 — simulating the year from M1). `Jadual: jwg-20260101-simulasi.md, jwg-20261002.md` — the first is a labelled copy of the 5.10.2026 timetable valid from 1 Jan (only the October timetable is converted); `Rekod` and `Output` point at `../output/simulasi-4S-M3`. For real use: Rekod `../rekod/2026`, Output `../output/rph`, Mula = the class's current SP.
- The full list of seven class × subject rows is kept as test data in `test/data/kelas-semua.md`.
- `DSKP`, `RPT`, `Tutorial`, `Mula` may be blank. `Bil. murid` is required before that class is planned. `Mula` (first SP to teach) is required when the class has a DSKP and its rekod is empty.

### 3.3 Events — `acara-<tahun>.md` (new: `sample/acara-2026.md`)
```
## Hari acara
| Tarikh | Acara | Tingkatan |        Tingkatan blank = all forms; else e.g. "1, 2"
## Batal
| Tarikh | Sasaran | Sebab |         Sasaran blank = everyone; "4" = Form 4; "4S" = class 4S
```
Hari acara → lessons flagged (the teacher decides). Batal → no lesson at all.

### 3.4 Activity template — `aktiviti-<nama>.md` (new: `sample/aktiviti-umum.md`)
Bullet lists under `## Permulaan`, `## Perkembangan`, `## Penutup`. Durations are not in the file: Permulaan 5 min, Perkembangan = lesson minutes − 10, Penutup 5 min.

### 3.5 Rekod — `<Rekod>/rekod-<kelas>-<subjek>.md` (written by the CLI, edited by the teacher)
```
| Minggu | Tarikh | Hari | Waktu | Masa | Jenis | Acara | SP | Status | Kehadiran | Catatan |
| M35 | 2026-10-05 | Isnin | 2–3 | 7:30–8:30 | pdp | | 6.2.1 | diajar | 35 | |
```
- `Jenis`: `pdp` · `tutorial` · `peperiksaan`. `Acara`: event or exam name (generated).
- `SP`: codes in order, read loosely: every `n.n.n` code, or topic code `n.0` for a revision lesson (`4.2.7, 4.2.8`, `4.2.7 + 4.2.8` and pasted SP text all work). Topic and SP codes may not be mixed in one row.
- `Status`: `diajar` · `ditunda` · `batal` (any case); blank for peperiksaan. Unknown words fail.
- `Kehadiran`: leading number is read (`33/35` → 33). Blank for peperiksaan.
- `Catatan`: reason (ditunda / batal) or reflection.
- The header text above the table is regenerated on every write; only table rows are data.

### 3.6 RPT appendix — added to `rpt-<subjek>-<tahun>.md`
```
## Peruntukan SP
| SP | Minggu |
| 6.2.1 | 0.549 |
```
Weeks per SP (3 decimals) = the planner's `panjang`. The weekly table and everything above it are unchanged. `rpt-mat-t4-2026.md` is regenerated once to add it.

CLI: `src/cli/rph.js` (thin: reads files, calls the core, writes files, prints) and `src/cli/simulasi.js` (runs `rph.js` week by week as if on each Saturday before, no edits).

## 5. Algorithms

### 5.1 Scheduler (one takwim week)
For each weekday of week `Mn`: take the jadual version in force that day; for each slot that day find the class row (`Subjek` match → `pdp`; `Tutorial` match → `tutorial`; none → skipped, and the CLI prints `Tidak dirancang (tiada dalam fail kelas): …` once). Then:
- form holiday (`dayClass` = cuti) → no lesson; Batal match → no lesson;
- form exam (`dayClass` = exam) → `jenis: 'peperiksaan'`, `acara` = exam name(s);
- Hari acara match (same date, form in list or list empty) → `acara` = event name(s), joined with `; `.
Lessons sorted by date, then first period. `minit` = periods × 30.

### 5.2 Pacing (`planRows`)
State: `idx` (current SP in DSKP order, starts at `Mula`, else 0), `sisa` (minutes left of `sp[idx]`, or null if not started), `ulang` (revision lessons so far), `akhirDiajar` (SPs of the latest diajar pdp row).
`perlu(i, row)` = `masaSp.get(code)`; without an RPT (`masaSp` null), = the row's minutes (one SP per lesson); SP missing from the appendix → row minutes + warning.

`masaSp` (in `masa-sp.js`): the RPT's capacity weeks are the RPT table weeks that list SPs, in order. SP k occupies `[Σ weeks of SPs before k, + its weeks]` on that axis; its minutes = Σ over capacity week i of overlap × `minitPdpMinggu(week i)` (the class's scheduled pdp minutes that week, from the scheduler; before the first timetable's date the earliest timetable is used and the CLI warns `tiada jadual sebelum <date>`). Sum of all SP minutes = the class's minutes in all capacity weeks.

Rows are processed in date/time order. For a **new** row (`baru: true`):
- pdp → **generate**: starting from `idx` with `ada = minit`: add the SP; if `remaining − ada ≥ 15` stop (it continues next lesson); else it finishes here, `ada −= remaining`, move to the next SP, stop if `ada < 15` or the DSKP ends. If the DSKP was already finished: `[topic[ulang % topics]]`.
- tutorial → `akhirDiajar`; peperiksaan → `[]`.

Then every **diajar pdp** row (new or old) is **replayed**: all listed SPs but the last are finished; the last gets `max(0, minit − Σ remaining of the others)`; it is finished when < 15 min of it remains, else it becomes `idx` with that `sisa`. **Without an RPT** nothing spans lessons, so every listed SP is finished (a hand merge such as ASK `4.2.7, 4.2.8` moves on to 4.2.9). Topic-code rows add to `ulang`. Unknown codes fail with `file:line`. Generation and replay give the same state, so generated rows replay to themselves, and hand-edited rows (merges, re-teaching) are honoured.

`akhir = { idx, sisa, ulang, selesai: idx ≥ sp.length }`.

### 5.3 Revision
A row whose SP cell holds topic codes renders the topic's SKs and SPs under Tajuk `ULANG KAJI: n.0 …`.

### 5.4 Sync (`syncRekod`) — one class × subject
- **Edited** row: Status ≠ default (`diajar`; blank for peperiksaan), or Catatan not empty, or Kehadiran ≠ default (class size; blank for peperiksaan). **To lock a future row's SP, write a note in Catatan** (an SP change alone is not detectable).
- **Kept** rows: tarikh ≤ hariIni, or edited. Future unedited rows are dropped and rebuilt.
- **Weeks planned**: rekod empty → only `minggu`. Otherwise from `min(last rekod week + 1, earliest future row's week)` to `max(minggu, last rekod week)`. Skipped weeks are planned too and warned about — only weeks that actually have lessons (a full holiday week such as M6 is not "skipped").
- For every scheduled lesson of this class × subject in those weeks: skip if a kept row has the same date and first period; skip past lessons in weeks that already had rows (the teacher deleted them); otherwise add a new row (diajar, class size; peperiksaan: blank status and kehadiran).
- A kept future row with no matching slot → warning "tiada dalam jadual" (row kept unchanged).
- Rows sorted by date/time, then `planRows`. Fails if the rekod is empty and the class has a DSKP but no Mula, or if Bil. murid is blank.
- Running twice with the same inputs gives identical files.

### 5.5 Summary (`ringkasanKelas`)
State before week `minggu` = `planRows` over rows with `minggu < n`. Next SP = `sp[idx]`; its RPT span (first–last week listing it) is shown for reference.
- `diajar` = minutes of SP content done (Σ `masaSp` of finished SPs + used part of the current one). `jangka` = Σ `minitPdpMinggu` over teaching weeks (≥ 1 PdP day for the form) before `minggu`. `beza = (diajar − jangka) ÷ seminggu`, where `seminggu` = the class's minutes in the timetable in force that week (4S: 210).
- `|beza| < 0.5` → `ikut RPT`; otherwise `round(|beza|) minggu ke depan / ke belakang`. Measuring in minutes keeps a partial week (M20: 60 min) from inflating a few minutes into "1 week".
- Line: `4S M3: SP 2.1.1 · RPT M5 · ikut RPT`. Others: `DSKP selesai · ulang kaji`, `tiada RPT`, `tiada DSKP`, `SP x tiada dalam RPT`.
- Fit warning when the minutes needed for the remaining SPs exceed the scheduled pdp minutes from `minggu` to the RPT's `Sukatan tamat` week by more than one period (30 min — the 15-minute rule can add a little): `perlu X minit …, ada Y minit hingga M34; pertimbang gabung SP`.
- **Simulated 2026 (4S, no disruption):** `ikut RPT` every week M1–M34, DSKP done at the end of M34, revision M35–M36, PAT M37. With all three M10 lessons ditunda: `1 minggu ke belakang` from M11, fit warning every week, DSKP done in M35.

## 6. RPH page (`render/rph.js`)
One A4 portrait page per row (batal rows are not printed), labels as in `sample/2026 - ASK T1 - Google Sheets M34A.pdf`:
header `2026 - ASK T1` … `M35`; `RANCANGAN PENGAJARAN HARIAN`; NAMA GURU; MATA PELAJARAN (tutorial: `… (TUTORIAL)`); MINGGU / TARIKH / HARI (`35 05/10/2026 ISNIN`); TINGKATAN (`4 STANFORD`); MASA (one `0800 - 0830` line per period); KEHADIRAN (`35 / 35`); CATATAN only when `acara` (`Hari acara: X-Break` / `Peperiksaan: PAT TING. 4`); TAJUK (upper case; `PEPERIKSAAN` for exams); STANDARD KANDUNGAN; STANDARD PEMBELAJARAN; OBJEKTIF PEMBELAJARAN (`Murid dapat:` + SPs); RINGKASAN AKTIVITI (`Permulaan: (5 minit)`, `Perkembangan: (50 minit)`, `Penutup: (5 minit)`); REFLEKSI (three lines, ☑ on the one that applies; ditunda → `☑ PdP ditunda kerana: <Catatan>`; diajar with Catatan → Catatan printed below). Exams print TAJUK `PEPERIKSAAN` and no SP, objective, activity or reflection.

## 7. CLI
```
node src/cli/rph.js --kelas sample/kelas-2026.md --minggu 35 [--hari-ini 2026-10-03]
```
- `--minggu` accepts `35` or `M35`. `--hari-ini` defaults to the local date.
- For each class row: read rekod (if any) → `syncRekod` → write rekod → collect rows for each planned week plus `minggu`.
- Writes `<Output>/<tahun>-M<n>-<SUBJEK>.html` for each subject and week with printable rows (all classes of that subject in one file, by date/time).
- Prints the files written, then `Amaran: …` lines (stderr), then one summary line per class.
- **All or nothing**: every class is processed first; files are written only when all succeeded. On any error: `Ralat: <message>` on stderr, exit code 1, no files changed, no stack trace.

```
node src/cli/simulasi.js --kelas sample/kelas-2026.md [--dari 1] [--hingga 43]
```
Runs `rph.js` for each week as if on the Saturday before it, no rekod edits, and prints `M<n> (<Saturday>) <summary line>` plus any warnings (except the early-timetable one). Used to check that an undisturbed class tracks the RPT.

## 8. Errors and warnings
**Stop** (message names file and line where there is one): bad table structure or column count; Masa ≠ Waktu; unknown Hari / Jenis / Status; bad Tarikh; SP or topic code not in the DSKP; topic and SP codes mixed; no jadual version for a planned lesson date; week not in the takwim; empty rekod with DSKP but no Mula; blank Bil. murid; RPT without `## Peruntukan SP`; activity template missing a section.
**Warn and continue**: no DSKP; no RPT; SP missing from Peruntukan SP; skipped weeks planned; kept future row without a slot; remaining SPs won't fit before the syllabus end; no timetable before a date used for SP minutes. **Note**: timetable slots of classes not in the class file.

## 9. Testing
`node test/<file>.js` with `node:assert`, against the real files in `sample/` (plus small inline fixtures for edge cases); `node test/semua.js` runs every test file. Coverage: Jadual parse on `jwg-20261002.md` (12 slots, `12:30–2:00`, wrong Masa fails); resolver across two versions; class / acara / aktiviti / RPT appendix parsing; scheduler on M35 (12 lessons), M36 (X-Break), M37 (Form 4 exams only), M38 (all exams), M39 (2 Nov holiday); rekod round-trip, CRLF, loose Status / SP / Kehadiran; pacing worked examples (shared lesson, spanning SP, 15-min rules, ditunda, hand merge, tutorial, revision, no RPT); sync (kept vs rebuilt rows, skipped weeks, deleted past lesson, slot gone, rows out of order, idempotent); summary (ikut / ke depan / ke belakang, fit warning); RPH HTML labels and durations; one end-to-end CLI run in a temp folder, re-run byte-identical.

## 10. Clarifications made while writing this spec
- **Untouched rows**: an SP-only edit on a future row can't be told apart from a generated SP, so the rule is "Status, Kehadiran or Catatan changed". To keep a future SP edit, write a note in Catatan.
- **"Slot tiada"** is a warning in the CLI output; the row itself is left unchanged.
- **CLI takes `--kelas <file>`** instead of `--tahun`: the class file names the year, takwim, jadual, acara and folders.
- **Real class data**: `sample/kelas-2026.md` is created with Bil. murid and Mula blank; the teacher fills them before the first real run.
- **No-RPT merges** (found while dry-running the plan): without an RPT every SP listed in a diajar row counts as finished; otherwise the ASK sample's `4.2.7, 4.2.8` would re-teach 4.2.8.
- **All-or-nothing writes** (found while dry-running the plan): a typo in one rekod must not leave other classes' files half-updated.
- **SP time from the RPT's actual weeks** (teacher's choice after the full-year simulation): the first version (weeks × 210 min) let an undisturbed 4S drift 2 weeks behind because the RPT counts partial holiday weeks as whole weeks.
- **One class only for now** (teacher's choice): 4S Matematik, simulated from M1; unlisted timetable slots are skipped.
